## 1. 결정한 것

### 시작 안내는 짧게
- 기능을 다 설명하면 TTS로 1분 가까이 걸린다(TTS가 천천히 읽음). 그래서 **처음 실행 때 전체 설명을 자동으로 읽는 방식은 하지 않기로 함.**
- 시작 안내 기본형:
  > 씨나리오가 준비되었어요. 사용법이 궁금하면 화면을 누르고 '사용법'이라고 말해 주세요.
- 여기에 **조작으로도 사용법을 들을 수 있다**는 말을 덧붙인다(조작은 아래 2번에서 확정).
- 지금 문구(`voice/VoiceController.kt`의 `GREETING`):
  > 씨나리오가 준비됐어요. 화면을 누르고 '묘사해줘'라고 말해 주세요. 시끄러운 곳에서는 화면을 1초 동안 길게 누르면 바로 묘사해 드려요.

### 음성으로 사용법 부르기
- 휴대폰 명령으로 처리(에이전트로 보내지 않음). `CommandParser`에 새 명령 추가.
- 키워드 후보: "사용법", "도움말", "사용 설명" (+ "어떻게 써" 검토)
- **"설명" 하나만 키워드로 쓰지 않는다.** "이거 설명해줘" 같은 사진 질문까지 사용법으로 빠진다.

### TalkBack 여부를 앱이 안다
- `AccessibilityManager.isTouchExplorationEnabled` + 변경 리스너(`addTouchExplorationStateChangeListener`)로 실시간 감지 가능.
- 삼성/구글 TalkBack 등 "손으로 더듬어 읽는" 화면 읽기 기능이면 모두 true → 두 번 탭/두 손가락 조작을 쓰는 사용자와 정확히 일치.
- `voice/TalkBackSpeechMonitor.kt`(TalkBack이 말하는 중인지 감지)가 이미 있음.
- 이걸로 **시작 안내와 사용법 내용을 TalkBack 여부에 따라 다르게** 한다. 상관없는 설명이 빠져서 각각 짧아진다.

## 2. 제안 상태 (사용자 확인 필요)

### 사용법을 부르는 조작: 세로 스와이프
- **방향 상관없이 세로로 밀면 사용법** (가로 = 모드, 세로 = 사용법으로 외우기 쉬움)
- TalkBack 켜짐이면 **두 손가락 세로 스와이프**
- 지금 세로 스와이프는 "애매한 움직임"으로 무시 중이라 다른 기능과 겹치지 않음
- 주의
  - 위쪽 가장자리 = 알림창, 아래쪽 가장자리 = 홈 제스처 → "화면 가운데에서 밀기" 안내 필요
  - TalkBack 두 손가락 **세로**가 앱까지 오는지 실기기 테스트 필요 (가로는 확인됨)
- 다른 후보를 뺀 이유
  | 후보 | 문제 |
  |---|---|
  | 세 번 탭 | 첫 탭에서 듣기가 시작됨. 막으려면 모든 탭이 0.3초 늦어짐 |
  | 더 길게 누르기(3초) | 1초에서 묘사가 먼저 실행됨 |
  | 두 손가락 탭 | TalkBack에서 "말 멈춤" 동작과 겹침 |
  | 화면 버튼 | TalkBack에서 두 번 탭이 포커스에 따라 바뀌는 문제 |

### 시작 안내 문구 (TalkBack 여부별, 초안)
- TalkBack 꺼짐: "씨나리오가 준비되었어요. 사용법이 궁금하면 화면을 위아래로 밀거나, 화면을 누르고 '사용법'이라고 말해 주세요."
- TalkBack 켜짐: "씨나리오가 준비되었어요. 사용법이 궁금하면 두 손가락으로 화면을 위아래로 밀거나, 두 번 탭하고 '사용법'이라고 말해 주세요."
- 음성 인식을 못 쓰는 기기(`GREETING_NO_SPEECH`)는 '사용법' 말하기 부분을 뺀다.

### 사용법을 화면 글자로도 띄우기 (제안)
- TalkBack 사용자는 글자를 한 줄씩 넘기며 다시 듣거나 필요한 부분만 들을 수 있다(TTS는 놓치면 되돌릴 수 없음).
- 지금 결과 글씨가 나오는 아래쪽 자리에 띄우는 방안.

### 사용법 내용 (뼈대만, 4가지 모드 확정 후 작성)
- TalkBack 꺼짐: 탭하면 듣기 / 1초 누르면 바로 묘사 / 가로로 밀면 모드 바꾸기 / 세로로 밀면 사용법 / 말로 하는 명령 몇 개
- TalkBack 켜짐: 가운데를 한 번 탭해서 고른 뒤 두 번 탭하면 듣기 / 두 번 탭하고 누르고 있으면 바로 묘사 / 두 손가락으로 가로로 밀면 모드 / 두 손가락 세로로 밀면 사용법
- 공통: "화면 가장자리 말고 가운데에서 밀어 주세요"(가장자리는 뒤로 가기·알림창·홈과 겹침)
- 묘사 명령 예시는 대표 표현만: "묘사해줘", "주변 알려줘", "뭐가 보여?"
- 짧게 유지할 것. 읽는 중 화면을 탭하면 멈추고 듣기로 넘어가는지 구현 때 확인.

## 3. 보완할 점 (따로 기록해 둔 것)

- **듣기 시작 신호 없음**: 탭해도 앱이 소리·진동을 안 낸다(화면 "듣는 중" 표시뿐, 기기 인식기 "띵"은 기기마다 다름). 마이크가 켜진 줄 모르고 한 "이거 왜 안 돼"가 AI로 갈 수 있다 → 소리/짧은 안내/진동 중 하나 추가.
- **"주변"/"풍경" 키워드**: 들어 있기만 하면 묘사(`DESCRIBE`)로 간다. "주변에 화장실 있어?" 같은 질문도 대화가 아니라 묘사로 처리됨.
- **CLAUDE.md에 스와이프 반영 안 됨**(PR #30). 공용 파일이라 팀원에게 알린 뒤 반영.

## 4. 참고: 지금 조작 정리 (PR #30 병합 후)

| | TalkBack 꺼짐 | TalkBack 켜짐 |
|---|---|---|
| 듣기 | 탭 | 두 번 탭 |
| 바로 묘사 | 1초 누르기 | 두 번 탭하고 누르고 있기 |
| 모드 바꾸기 | 가로 스와이프(방향 무관) | 두 손가락 가로 스와이프 |
| 비어 있음 | 세로 스와이프(지금은 무시) | 두 손가락 세로 스와이프 |

- 터치 판정: 32dp 안에서만 움직이면 탭/길게 누르기, 가로로 화면 너비 1/4 이상 + 가로가 세로의 2배 이상이면 스와이프, 그 외 무시.
- 코드 위치: `SeenarioScreen.kt`의 탭 영역 `pointerInput`, 규칙은 `sound/SoundModeSwipe.kt`(`classify`). 세로 스와이프를 넣으려면 `classify`에 세로 조건을 추가하면 된다.

## 5. 참고: 실기기 테스트 방법

- 테스트 기기: 갤럭시 A24(SM-A245N), 삼성 TalkBack
- adb `uinput` 명령으로 가상 터치스크린을 만들어 한 손가락/두 손가락 터치를 넣을 수 있다(`sendevent`는 SELinux가 막음).
- TalkBack 켜기/끄기:
  - 켜기: `adb shell settings put secure enabled_accessibility_services com.samsung.android.accessibility.talkback/com.samsung.android.marvin.talkback.TalkBackService` + `adb shell settings put secure accessibility_enabled 1`
  - 끄기: `adb shell settings delete secure enabled_accessibility_services` + `adb shell settings put secure accessibility_enabled 0`
- 가상 터치로는 TalkBack 두 번 탭이 재현되지 않는다(dev 버전도 같음). 두 번 탭은 손으로 확인.
- `USE_FAKE_AGENT=false`면 스와이프·묘사 테스트마다 실제 Gemini 호출이 나간다.
