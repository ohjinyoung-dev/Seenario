# 🎧 씨나리오 (Seenario) - 팀 버저비터

**"기능적 보조를 넘어, 머무는 공간의 분위기를 온전히 누릴 권리"**

## 📌 1. 프로젝트 개요 및 기술 스택

### Rule 1. `master` 브랜치 직접 수정 및 병합(Merge) 절대 금지
* `master`는 최종 배포 및 경진대회 제출용 브랜치입니다.

### Rule 2. 모든 개발은 개인/기능 브랜치에서 작업 후 `dev`로 병합
**`dev` 브랜치:** 두 사람의 코드를 합쳐서 통합 테스트를 진행하는 중심 브랜치입니다.
**`feat/기능명` 브랜치:** 각자 코딩할 때는 반드시 `dev`에서 새 브랜치(예: `feat/camera`, `feat/vui`, `feat/audio`)를 파서 작업합니다.
* 작업이 끝나면 바로 `dev`에 강제 병합하지 않고, **Pull Request(PR)**를 올려 서로 확인한 뒤 `dev`로 합칩니다.

### Rule 3. 작업 시작 전 무조건 `dev` 최신화(Pull) 먼저 하기
* 코딩을 시작하기 전, 항상 `dev` 브랜치의 최신 변경 사항을 내 컴퓨터로 먼저 받아온(Pull) 뒤 작업을 시작합니다. (충돌 방지 1순위)

### Rule 4. API 키 및 민감 정보 커밋 절대 금지 (보안)
* Supabase URL/Key, Gemini API Key, Claude API Key 등 모든 시크릿 키는 코드(`.kt`, `build.gradle.kts` 등)에 직접 적지 않습니다.
* 모든 키 값은 반드시 프로젝트 루트의 **`local.properties`** 파일에만 작성하며, 새 키가 추가되면 카톡/디스코드로 공유합니다[cite: 17].

## 💬 3. 커밋 메시지 컨벤션 (간단 규칙)
나중에 히스토리를 알아보기 쉽게 커밋 메시지 앞에 아래 태그를 붙여서 작성합니다.

* `[Feat]` : 새로운 기능 추가 (예: `[Feat] 빅스비 음성 호출 인텐트 연동`)
* `[Fix]` : 버그 및 에러 수정 (예: `[Fix] 카메라 캡처 시 앱 크래시 오류 해결`)
* `[UI]` : 레이아웃 및 디자인 수정
* `[Refactor]` : 기능 변경 없는 코드 정리 및 구조 개선
* `[Chore]` : 라이브러리 추가, 빌드 설정(`gradle`), `.gitignore` 등 기타 수정
